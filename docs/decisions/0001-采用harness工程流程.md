# 0001：采用 AI 主导的 harness 工程流程

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-25 |
| 相关 | [SOP.md](../SOP.md) |

## 背景

后续开发希望大部分工作由 AI（Claude Code、Codex）完成，人只在关键节点把关。AI 没有跨会话记忆，需要仓库本身承载上下文和纪律。

## 决定

- `AGENTS.md` 作为入口地图，`CLAUDE.md` 只引用它。
- `docs/` 作为知识库：设计、ADR、计划、references、质量与技术债、runbooks。
- 计划文件同时作为交接文件。
- 人只在三个关口介入：批准设计、批准计划、验收。
- `make check` 是唯一的质量关口：pre-commit 运行 `check-fast`，合并前在合并后的代码上运行完整的 `check`。
- 每份计划一个分支，以 `--no-ff` 合并到 main。

## 考虑过的其他方案

- **只靠一份长 CLAUDE.md**：不选的原因：入口膨胀、无法交接、约定无法机器检查。

## 影响

纪律主要靠 hook 和 `make check` 维持，所以要尽量把约定改成机器检查（SOP §10）。
