## 背景

搁架（Shelf，IntelliJ 概念）把一部分未提交改动存成有名字的条目、从工作区移走，之后可以取回。它和贮藏（stash）不同：只针对勾选的文件、有名字、不进 `git stash list`。参考项目把它存成工作区存储目录里的 `<id>.patch` + `shelf.json`。

约束同 ADR 0008：Host 的写入都经 `sandbox.confine`，不能用 `node:fs` 直接写仓库；沙箱里的 Agent 可能在 `.git` 里放符号链接；多个工作树不应互相看到对方的条目。

## 决定

每条搁架是一个提交对象，挂在 `refs/worktree/dsh-git/shelf/<id>`。它的树里有 `meta.json`（名字、创建时间、来源分支、基准 HEAD，以及每个路径在搁置时的三份对象：HEAD 条目、索引条目、工作区条目，各为 mode + blob），以及这些 blob 本身（作为树条目，保证 `gc` 不回收）。工作区内容由 `git hash-object -w` 读取并写入对象库，索引条目用 `ls-files -s` 读取——**字节从不经过 JavaScript 字符串**，所以编码、textconv、diff 前缀、输出大小都不会让条目失真（B3c 终审 C2/I1）。

取回时经索引写回（`update-index --index-info` + `checkout-index -f`），完整恢复已暂存与未暂存两层（终审 I2）；只有当这些路径仍与搁置时的 HEAD 完全一致才算干净应用。三方合并逐文件用 `git merge-file --object-id`（需要 git ≥ 2.43），冲突写成索引的 1/2/3 阶段，冲突列表直接可用；留下冲突的条目一律保留（终审 C1）。

顺序：采集 → 校验这些路径在采集期间没有被改动（Agent 同时在改，终审 I4）→ 写 ref → 回滚。写 ref 之前任何一步失败都不改动工作区；没有任何提交的仓库直接拒绝（终审 I3）。全部写入经受限 git。

（初版用 `git diff --binary` 生成补丁文本存为 blob；终审发现非 UTF-8 文件、textconv、`diff.noprefix` 都会让补丁无法还原而工作区已被回滚，2026-10-28 改为本方案。）

## 考虑过的其他方案

- **工作区文件（`.idea/shelf` 或 `<gitDir>/dsh-git/shelf/*.patch`）**：不选的原因：需要 `node:fs` 在 confine 之外写；Agent 能看到并改动。
- **存补丁文本（初版）**：不选的原因：见「决定」末段。
- **用 `git stash push -- <paths>` 再把条目移到自己的 ref**：不选的原因：会短暂占用用户共享的 stash 栈（其他会话可能同时 pop），并且 `stash` 不支持只记录「名字 + 文件」之外的元数据。
- **共享的 `refs/dsh-git/shelf/*`**：不选的原因：多个工作树共享命名空间。

## 影响

- `git gc` 不会回收（ref 可达），也不会被推送（不在 `refs/heads`/`refs/tags`）。
- 删除工作树时条目随之消失（`refs/worktree/*` 按工作树存放）。
