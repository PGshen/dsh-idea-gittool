## 目标

把 `1.0.0-rc.1` 作为公开 GitHub Release 发出去：任何人拿到 Release 链接，用一条 `dsh plugin --profile web add <tgz URL>`（或在 Web 的 Plugins 页粘贴同一 URL）装好 Git 工作台。仓库同时具备可重复构建、校验和、Release 说明与撤回方式的发布流程。

## 范围

**包含：**

- 包元数据与许可证：`license`、`repository`、`homepage`、`keywords`、`author`、`LICENSE`，以及（如确认移植参考项目代码）`NOTICE` 与致谢。
- `CHANGELOG.md` 与版本策略：首发 `1.0.0-rc.1` → 反馈后 `1.0.0`；`engines.dsh` 跟随 DSH 版本。
- `make dist` / `pnpm dist`：构建 → smoke → `pnpm pack` → `SHA256SUMS` → 打印安装命令。
- `prepack` 守卫：任何打包/发布前强制重新构建并跑 smoke，避免发出旧 `lib/`。
- 发布 runbook `docs/runbooks/release.md`：版本 bump、tag、GitHub Release、校验、隔离 HOME 复验、撤回。
- README 面向收件人的安装段（全局 `dsh plugin` / checkout 内 `pnpm dsh plugin` / Web Plugins 页），平台与 DSH 版本支持说明。
- 首次公开发布 `v1.0.0-rc.1`（负责人执行 tag 推送与 Release 上传）。

**不包含：**

- `npm publish`（T1 的元数据为它铺路，发布动作后续单独决定）。
- 插件市场 index（Discover 入口；安装目标只能是 npm 或 `git+url#commit`，依赖上一项）。
- 英文 README（公开后如需再单独做）。
- 让公开仓库的源码构建开箱即用（`devDependencies` 的绝对 `link:` 路径改为可配置属贡献者体验，后续单独处理；只装 tgz 的收件人不受影响）。
- 功能改动、Windows/Linux 真机验证、旧版 git 兼容实测。
- CI 自动发布（`.github/workflows` 后续另立计划）。

## 验收标准

- [ ] AC1：干净 clone 上 `make dist` 产出 `dist/dsh-idea-gittool-<版本>.tgz` 与 `SHA256SUMS`；`pnpm pack --dry-run` 清单与 `test/bundle.smoke.mjs` 的契约一致（8 个文件，含 `LICENSE`/`NOTICE`，不含 CSS 副本与 sourcemap）。（验证方式：`make check` + `make dist` + `tar -tzf`）
- [ ] AC2：隔离 HOME 用 Release URL（无外网时用本地 tgz 代替）安装 → 重启 → 打开 Git 标签可用；升级/卸载表现与 [安装升级 runbook](../../runbooks/install-upgrade.md)「实测」一致。（验证方式：runbook 步骤 + 证据写入「验证记录」）
- [ ] AC3：新收件人只读 README「安装」一节就能完成安装，命令、URL、重启、卸载、平台限制齐全。（验证方式：负责人通读）
- [ ] AC4：`docs/runbooks/release.md` 能从版本 bump 一路走到 Release 上传与撤回，30 分钟内可执行完。（验证方式：按 runbook 实际走一遍，记录耗时）
- [ ] AC5：公开仓库无敏感信息：`.evidence/`、密钥、真实仓库数据未入库；`git ls-files` 抽查通过。（验证方式：`git ls-files` + `grep` 检查）
- [ ] AC6：`make check` 全绿；发布 runbook 中的校验和命令在收件人机器上可用。（验证方式：`make check`、`shasum -a 256 -c SHA256SUMS`）

## 任务

### T1：许可证、包元数据与公开仓库检查（完成）

- **目标**：包在 GitHub / npm 上元数据完整、许可证明确；公开前没有内部信息。
- **涉及文件**：`LICENSE`、`NOTICE`（如需）、`package.json`、`README.md`、`docs/references/reference-feature-inventory.md`（复用边界复核）。
- **接口与要点**：
  - 许可证候选：MIT（与 DSH 一致，推荐）或 Apache-2.0（若确认移植了 IdeaGitTool 的纯逻辑代码，则保留其署名与 NOTICE）；
  - `package.json` 增加 `license`、`repository`、`homepage`、`keywords`、`author`，不设 `private`；
  - 复核 `src/` 是否包含参考项目的原样代码（对比算法/注释），把结论写进「决策记录」。
- **测试**：`npm pkg get license repository homepage keywords author` 字段齐全；`pnpm pack --dry-run` 包含 `LICENSE`；`make check`。
- **完成标准**：许可证文件存在且被包包含；元数据可被 `pnpm view` 读取；公开仓库抽查无敏感文件。
- **验证命令**：`make check`、`pnpm pack --dry-run --json`

### T2：CHANGELOG 与版本策略（待开始）

- **目标**：每次发布有可读的变更记录；版本号规则固定。
- **涉及文件**：`CHANGELOG.md`、`docs/runbooks/release.md`、`package.json`。
- **接口与要点**：Keep a Changelog 结构（Added / Changed / Fixed / Security）；从 `1.0.0-rc.1` 起记录；说明 `engines.dsh` 跟随 DSH 0.2.x，DSH 升到 0.3 前必须发兼容版本；rc 转正式版的判定条件。
- **测试**：`scripts/check_docs.py` 不报错；CHANGELOG 首条版本与 `package.json` 一致。
- **完成标准**：CHANGELOG 覆盖 rc.1 的主要能力与已知限制。
- **验证命令**：`make check-docs`

### T3：`make dist` 发布产物（待开始）

- **目标**：一条命令产出可发布的 tgz、校验和与安装说明。
- **涉及文件**：`scripts/dist.mjs`（新）、`package.json`、`Makefile`、`test/bundle.smoke.mjs`。
- **接口与要点**：
  - 顺序：`pnpm build` → `pnpm smoke` → `pnpm pack --pack-destination dist` → 写 `dist/SHA256SUMS` → 打印版本、大小、sha256 与安装命令；
  - 工作树不干净时警告但不阻断（发布前由人确认）；
  - `prepack` 调 `build` + `smoke`，保证任何 `pnpm pack` / 未来的 `publish` 都不会带旧产物；
  - `dist/` 已在 `.gitignore`。
- **测试**：先写 `test/dist.smoke.mjs`（断言产物名、`SHA256SUMS` 内容、tgz 内 8 个文件），再实现脚本；连续两次 `make dist` 的 sha256 一致。
- **完成标准**：`make dist` 在干净 clone 上一次通过；重复构建哈希一致。
- **验证命令**：`make dist`、`shasum -a 256 dist/*.tgz`

### T4：发布 runbook 与 README 分发说明（待开始）

- **目标**：任何维护者按文档能发布；任何收件人按 README 能安装。
- **涉及文件**：`docs/runbooks/release.md`（新）、`README.md`、`AGENTS.md`、`docs/runbooks/install-upgrade.md`。
- **接口与要点**：
  - runbook：发布前检查（`make check`、版本、CHANGELOG、干净树）→ `make dist` → 隔离 HOME 复验 → tag `v<版本>` → GitHub Release（附 tgz 与 `SHA256SUMS`，Release notes 从 CHANGELOG 摘）→ 公告 → 撤回（标 pre-release / 删附件 / 发补丁版本）；
  - README：全局 `dsh plugin`、checkout 内 `pnpm dsh plugin`、Web Plugins 页三种装法；收件人校验和命令；平台与 DSH 版本范围；
  - AGENTS 命令表加 `make dist`，文档索引加 release runbook。
- **测试**：`scripts/check_docs.py` 的链接与章节检查通过；README 步骤在隔离 HOME 实测。
- **完成标准**：runbook 与 README 互相链接；AGENTS 不超过 120 行。
- **验证命令**：`make check-docs`

### T5：首发 GitHub Release v1.0.0-rc.1（待开始，负责人执行远程动作）

- **目标**：公开发布第一个可安装版本。
- **涉及文件**：`CHANGELOG.md`、`README.md`、`docs/plans/TODO.md`。
- **接口与要点**：
  - 本地：`make check` → `make dist` → 隔离 HOME 复验 → 记录 sha256；
  - 负责人执行：`git tag v1.0.0-rc.1 && git push origin v1.0.0-rc.1`；GitHub Release 上传 tgz 与 `SHA256SUMS`，Release notes 从 CHANGELOG 摘；
  - 发布后：README 填 Release 链接，TODO 勾掉发布相关条目；收集首批反馈决定 1.0.0。
- **测试**：在另一台机器或隔离 HOME 用 Release URL 安装（负责人执行）。
- **完成标准**：Release 页面可下载且校验通过；新用户按 README 安装成功。
- **验证命令**：`dsh plugin --profile web add <Release URL>` + 重启 + 打开 Git 标签
