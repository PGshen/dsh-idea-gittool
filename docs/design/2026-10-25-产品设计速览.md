# Git 工作台 · 产品设计速览 v0.2

> 一页版，供快速查阅。完整设计见 [产品设计-v0.2.md](2026-10-25-产品设计-v0.2.md)；决策记录见 [产品设计决策-v0.2.md](2026-10-25-产品设计决策-v0.2.md)；调研见 [参考项目功能清单](../references/reference-feature-inventory.md) 与 [DSH 集成可行性](../references/dsh-integration-feasibility.md)。

## 1. 一句话定位

在 DSH 右侧栏放一个 **IntelliJ 风格的 Git 工作台**：默认看提交图与历史，一键审 Agent 改动的 diff，按文件勾选提交，顺手管分支、贮藏和冲突。不是另一个独立 Git 客户端，而是「对话旁边的 Git 面板」。

## 2. 入口与信息架构

```
右侧栏「开始」页
└── [Git 工作台] 卡片  ← 主入口
    （命令面板 / Alt+G 也可打开）

Git tab
├── 仓库栏：仓库名 · 分支 · ↑↓ · 获取/拉取/推送/刷新/⋯
├── 内部页：日志（默认） | 提交(3) | 分支 | 贮藏(2)
├── 覆盖页：Diff / 文件历史 / 冲突 / Push·Update 等表单
└── 状态栏：分支 · 修改数 · 冲突数 · 贮藏数 · Git 版本
```

- 一个 tab、四个平级页、一个覆盖栈；不做多套弹层混用。
- 三栏合并窗口是唯一自动使用宿主全屏的页面。
- 分支入口是工具条按钮/抽屉，不常驻 24px 竖条。
- 有未提交改动时，tab 标题显示小圆点；不弹 Toast 打扰对话。

## 3. 三个关键页面

### 日志（默认页）

```
┌ 仓库栏：dsh-idea-gittool   ⎇ main ↑1 ↓2   [获取][拉取][推送][⋯] ┐
├ 日志 | 提交 3 | 分支 | 贮藏 2                                    │
├ 筛选：🔍 文本或哈希 .* Aa  [分支▾][用户▾][日期▾]  [图选项▾][视图▾] │
├─────────────────────────────────────────────────────────────────┤
│ ●─┐ feat: 完成 Git 日志页                    [main][origin/main] │
│ │ ● fix: 窄屏详情抽屉                        Alice 10-24 18:12   │
│ │ ●─┐ merge: 合入分支保护                     Bob   10-24 17:40   │
│ ...                                                             │
├─────────────────────────────────────────────────────────────────┤
│ 详情：提交信息 / 作者 / 父提交 / 变更文件 / 点击文件看 diff       │
└─────────────────────────────────────────────────────────────────┘
```

- 三档响应式：Compact 单列 + 详情覆盖；Standard 上下分栏（默认约 648px 可用）；Wide 三栏。
- 分支面板：单击导航到分支 HEAD，双击过滤；签出只在分支页/右键菜单。
- 提交图最多 6 条色相区分 lane，超过用线型/透明度；颜色用 DSH 静态色 + `color-mix`（混 `label-primary`），不写死明暗色。

### 提交

- 变更树：冲突 / 已修改 / 新增 / 删除 / 重命名 / 未跟踪；三态复选、目录分组、搜索。
- **只提交勾选文件**，不污染暂存区（`git commit --only`）。
- Amend 支持「只改提交信息」（无文件勾选、索引干净）。
- 合并/拣选/回滚状态切换为「操作提交」：合并提交不带 pathspec；拣选/回滚走 `--continue`。
- 推送被拒 → 「Push Rejected」：拉取并变基 / 合并 / force-with-lease / 自动重试一次。
- 脏工作区做合并/变基 → 智能操作：先 stash，成功后恢复；冲突保留 stash。

### 分支 / 贮藏

- 分支页：搜索、最近/本地/远程/标签、收藏、ahead/behind、快捷动作（更新/提交/推送/新建/签出标签）。
- 右键菜单覆盖签出、新建、合并、变基、拉取、推送、重命名、删除、比较、设 upstream；标签有独立菜单。
- 贮藏：创建/应用/弹出/删除/预览；P1 加 Shelf 分段。
- 更新项目遇到上游强推：默认先建 `backup/<branch>-<ts>` 再重置。

## 4. 首发范围（原 P0 + 全部 P1，只发 1.0.0）

| 模块 | 首发包含 |
|---|---|
| 日志 | 提交图、搜索/分支/用户/日期/路径过滤、图选项、跳转、分支面板、提交详情、变更文件、统一/并排 diff、词级高亮 |
| 提交 | 变更树、按文件提交、Amend（含仅改信息）、提交并推送、回滚、加入 VCS、操作状态提交、Push Rejected、完整提交右键菜单 |
| 分支 | 列表/分组/搜索/收藏、签出/智能签出、新建/删除/重命名、合并/变基/拉取/推送、比较、标签操作、完整对话框 |
| 贮藏 | 列表/创建/应用/弹出/删除/预览；Shelf、Changelist |
| 冲突 | 冲突列表、按具体分支采用左/右侧、标记已解决、继续/跳过/中止；**三栏可编辑合并** |
| 高级 | 交互式变基、文件历史、Blame 视图、文档预览头部动作、比较模式、Worktree、Patch、Remotes、更多提交选项 |
| 全局 | 仓库状态、自动刷新、Git 控制台、只读模式、写能力门禁、中英双语、明暗主题、a11y |

**P2 仍不做**：多仓库合并日志/同步分支控制、子模块、LFS、Clone/Init、Local History、托管平台 PR/Issue、内置凭据。

### 4.1 编辑器装饰 / 行内 blame 结论

- **真正的编辑器装饰、光标行内 blame、CodeLens：做不了**。DSH 只有只读文档预览，没有可编辑编辑器/caret，文件树也没有行级装饰 slot。
- **能做的替代**：
  - **Blame 视图**：独立只读页，左侧逐行 gutter 显示短哈希/作者/日期，点击跳提交/diff；入口在文档预览头部、提交详情、变更文件右键、文件历史。
  - **文档预览头部动作**：`sidebar.right.tab.document.actions` 公共 slot，显示状态字母 `M/A/D/U` + `Blame` / `历史` / `Diff`。
  - **可选 Git Blame 渲染器**：通过 `documentPreviews` 注册，默认关闭，避免抢占默认代码预览。
- **文件树状态色**：不做；需要 DSH 新增行级 slot，可作为上游建议。
- 结论：覆盖「看某行是谁改的、什么时候改的、点进提交」的核心需求，但不承诺编辑器内联体验。

## 5. 技术方案（已调研）

```
Browser: Client half (右侧栏 tab / 页面 / store)
   │  ctx.connection.rpc.call('/dsh-git', method, payload, signal)  → POST JSON
Host:   RPC router → RepoResolver → GitExecutor
   │        sessionId → cwd（sessions/workingDirectory/persistence）
   │        ctx.subprocess + ctx.sandbox.confine 执行 git
   └        watch + workspaceFiles.changes + 可见时轮询
```

- 交付：**独立双面 bundle 包**（Host `main` + `./client` + `dsh.bundle.patch`），`dsh plugin --profile web add` 安装；不改 DSH 仓库。
- 构建：官方 tsdown preset 不能脱离 DSH 仓库，自写 esbuild 包装；客户端重建可热更，Host 改动/首次安装需重启 `dsh web`。
- 通信：通用 RPC `/dsh-git`（一元 JSON、无推送），Typert 生成器外部不可用；刷新用 `workspaceFiles.changes` + 3s 轮询。
- Git：`ctx.subprocess` + `ctx.sandbox.confine`，`GIT_TERMINAL_PROMPT=0`、`LC_ALL=C`、`--no-ext-diff`、`-c core.fsmonitor=false`；绝不拼 shell。
- **写能力门禁**：仓库根在沙箱外 → 只读模式（历史/diff 可用，写按钮禁用并说明），不静默放宽。
- 数据：分页 + 单文件 diff ≤256 KiB / 单响应 ≤4 MiB；所有响应带 version，丢弃过期结果。

## 6. 里程碑（一次发布，内部阶段）

| 阶段 | 交付 | 估时 |
|---|---|---|
| M0 | 设计确认 + 集成 spike（产物/挂载/status/log/沙箱/刷新/文档动作空页） | 0.5–1 天 |
| A1 | 只读日志：入口、仓库栏、日志+提交图、详情、diff、控制台、只读模式 | 3–5 天 |
| A2 | 提交闭环：变更树、按文件提交、Amend、提交并推送、回滚、写门禁 | 3–5 天 |
| A3 | 分支/贮藏/操作状态提交/Push Rejected/智能操作/冲突最小闭环 | 5–7 天 |
| B1 | 三栏合并窗口 | 4–7 天 |
| B2 | 文件历史、Blame 视图、文档头部动作、比较 | 3–4 天 |
| B3 | 交互式变基、完整提交菜单、Shelf、Changelist、Worktree、Patch、并排 diff | 5–8 天 |
| B4 | a11y、性能、i18n、跨平台、安装/升级验证、文档 | 3–5 天 |
| 合计 | 含缓冲，单人全职 | **约 6–9 周** |

- 内部 `0.1.0` → `0.4.0` 构建用于自测/内测；对外只发 **`1.0.0`**。
- 三栏合并、交互式变基、Worktree 用 feature flag 控制，完成验收后默认开启；不静默砍功能。

## 7. 已确认决策 / 仍可调整

**已确认**

1. 交付：**独立 bundle 仓库**。
2. 范围：**原 P0 + 全部 P1 一起做**，只发 `1.0.0`。
3. 默认页：**固定日志**。
4. 视觉：跟 DSH 主题，不套 IntelliJ 皮肤。
5. 编辑器：不做真正装饰/光标行内 blame；做 Blame 视图 + 文档预览头部动作。

**仍可调整（不阻塞实现）**：命名、打开时是否自动全屏、多会话、模型可见性、可选 Blame 渲染器是否默认开启。

**下一步**：确认后直接进入 M0 spike；通过后按 A1 → A2 → A3 → B1 → B2 → B3 → B4 推进，最终发 `1.0.0`。
