# 0012：样式只用 DSH 快照中的变量，状态色与静态色作文字时往正文色混 60%

## 背景

A1–A3 的样式引用了 4 个 DSH 运行时并不存在的变量（`--dsw-alias-state-success`/`-warn`、`--dsw-font-mono`、`--dsw-alias-interactive-bg-selected`），浏览器静默回退，状态色与等宽字体从未生效，评审和测试都没发现。改成真实名字后又暴露第二个问题：DSH 的 `--dsw-alias-state-success-primary`/`-warn-primary` 与 `--dsw-static-*` 色相在浅色主题白底上只有约 2.2:1，作为文字达不到设计 §15.5 的 3:1/4.5:1。

## 决定

1. **变量白名单**：插件 CSS 中无回退值的 `var(--dsw-*)` 必须出现在 `test/client/dsh-tokens.ts` 的快照里（从 DSH `packages/client/ui-theme/src` 提取，文件头记版本、日期与提取命令）。DSH 升级后按 TD-2 重新提取。
2. **文字色混色**：成功/警告色和 `--dsw-static-*` 作 `color:` 时一律写成 `color-mix(in oklab, var(<hue>) 60%, var(--dsw-alias-label-primary))`（实测浅色 ≥5.3:1、暗色 ≥8:1）。边框、背景、标记等非文字用途不受限。沿用设计 §15.3 提交图 lane 的混色思路，不写主题选择器、不写字面色。
3. **机器检查**：`test/client/pages/css-lint.ts` 对全部 `*.module.css` 执行上述两条，外加「无字面色」「有动画必有 `prefers-reduced-motion`」「`outline: none` 须登记 `FOCUS_EXEMPT` 并写明替代指示」。

## 考虑过的其他方案

- **只拦已知的错误名（B1 的做法）**：下一个拼错的名字照样漏过去。不选。
- **测试时直接读 DSH 仓库**：CI 与其他机器没有 DSH checkout。不选。
- **为浅色/暗色各写一套状态色**：违反 DSH「功能组件不写主题选择器」的约定（references §4.1）。不选。
- **改用 `--dsw-alias-label-*` 中性色表达状态**：失去颜色这一层编码；设计要求颜色 + 字母/图标双重编码。不选。

## 影响

- 新样式用到快照外的 DSH 变量会让 `make check` 失败；确认 DSH 确有该变量时，按快照文件头的命令重新提取。
- 状态色文字比 DSH 原色略暗（浅色）/略亮（暗色），色相不变。
- 若 DSH 将来提供面向文字的状态色变量（如 `-text`），应改用它并更新本 ADR 与检查。
