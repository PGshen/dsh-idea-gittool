# 0006：浮层菜单使用 DSH 菜单材质 token

## 元信息

| 项 | 值 |
|---|---|
| 状态 | 已采纳 |

| 相关 | [ADR 0005](0005-自建CSS-Modules管线.md)、[A1 计划](../plans/completed/a1-只读日志.md) 决策记录与走查记录、DSH `docs/web-styling.md` 组件规则 |

## 背景

ADR 0005 规定样式只用 `--dsw-alias-*` / `--dsw-static-*` token。A1 走查发现筛选菜单把阴影 token `--dsw-elevation-panel` 误当背景，弹层透明、与下层文字重叠；而 alias/static 里没有「浮层表面」的底色与阴影。DSH 的 web-styling 规范要求浮层用 elevation 阴影、`--dsw-specific-menu` 底色与 `--dsw-menu-backdrop-filter`，并且推荐用 ui-primitives 的 `MenuSurface` / `Menu` 包裹菜单内容。

## 决定

插件内的浮层菜单（筛选菜单、仓库栏「⋯」、分支右键菜单，以及以后新增的同类浮层）统一使用：

- `background: var(--dsw-specific-menu)`
- `box-shadow: var(--dsw-elevation-panel)`，`border: 0`
- `backdrop-filter: var(--dsw-menu-backdrop-filter)`

这是对 ADR 0005 token 白名单的明确例外，只适用于浮层表面；普通组件仍只用 alias/static。插件自定义变量不得占用 `--dsw-` 命名空间（如 `--git-tree-depth`）。

## 考虑过的其他方案

- **只用 alias token 拼底色（`--dsw-alias-bg-layer-1` + 边框）**：与 DSH 其它菜单材质不一致，且规范明确禁止边框与 elevation 阴影叠用。不选。
- **立即改用 `MenuSurface` / `Menu`**：是正式做法，但要重写三个菜单的结构与键盘交互，超出 A1 只读范围。已记入 TODO（P2），届时本 ADR 的材质例外随之失效。

## 影响

- 浮层与 DSH 原生菜单观感一致，深浅主题由 DSH 主题负责。
- 依赖 DSH 主题 token 的稳定性：升级 DSH 后需确认这三个 token 仍存在（随 references §13 清单一起复查）。
- 迁移到 `MenuSurface` 后，把本 ADR 状态改为「被 <编号> 取代」。
