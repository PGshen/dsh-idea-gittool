## 目标

用户在 Git tab 的「提交」页里勾选文件、写提交信息，只提交勾选的文件（不污染暂存区），可以 Amend（含只改信息）、提交并推送、回滚改动、把未跟踪文件加入版本控制；推送被拒时有可行动的处理页。所有写操作经过写能力门禁，沙箱外只读。顺带收掉 A1 遗留：中英双语（TD-6）与前台 fps 证据（AC3）。

## 范围

**包含：**

- Host 写基础设施：写命令执行（`sandbox.confine`、本地写 60s / 网络 180s 超时、写环境）、每仓库写队列、每次写请求的门禁、写后 bump version。
- 写端点：只提交勾选文件、仅改信息 Amend、提交并推送、回滚、加入 VCS、推送（含 `--force-with-lease`）、推送预览、按方式拉取（只服务 Push Rejected）。
- 提交页（Level 0 第二页）：内部导航（日志 / 提交 + 未提交数徽标）、变更树（分组、三态目录、搜索、右键）、提交信息（草稿、历史、长度提示、`Cmd/Ctrl+Enter`）、提交动作、操作状态下禁用并说明。
- 覆盖页与浮层：Push、Push Rejected、回滚确认（未跟踪文件删除走危险确认）。
- Tab 标题未提交圆点（§5.3），提交成功反馈（§14.4）。
- A1 遗留：TD-6 全部页面文案进 `gitWorkbench` 命名空间并补英文；AC3 前台 fps 录制；跳转失败说明从 `title` 改为可见文本。

**不包含：**

- 操作状态下的提交（合并/拣选/回滚的继续提交）、冲突列表、分支动作、贮藏、Update Project、Fetch 对话框（A3）。
- 作者/签名面板、Changelist、`.gitignore`、补丁、跳过 hooks（P1，B3）。
- 并排 diff 等 B 阶段能力；菜单迁移 `MenuSurface`（TODO P2）；TD-5 嵌套 refs 监听（A3 前）。

## 验收标准

- [ ] AC1：写门禁——`repoRoot` 在 `workspaceRoot` 内或 `danger-full-access` 时写端点可用；沙箱外所有写入口禁用并显示只读说明；门禁不可判定时写端点返回 `git/sandbox-denied`（Host 单测覆盖三种情况 + 实机截图）。
- [ ] AC2：勾选 2/5 个文件提交后，`git status` 证明只有这 2 个进入提交，其余改动（含已暂存的无关改动）原样保留（真实临时仓库测试）。
- [ ] AC3：未跟踪文件可勾选提交；删除、重命名正确；路径含空格、Unicode、以 `-` 开头都正确（真实仓库测试）。
- [ ] AC4：无勾选 + Amend = 仅改信息可用；暂存区有未勾选改动时拒绝并给出说明，不带走无关改动；HEAD 已推送时显示改写历史警告（单测 + 实机）。
- [ ] AC5：hook 失败显示「提交被 Git hook 阻止」+ 输出摘要 + 「查看 Git 控制台」，不自动 `--no-verify`；失败后工作区与索引恢复到提交前（含 `add -N` 留下的 intent-to-add 被撤销）。
- [ ] AC6：提交并推送：有 upstream 直接推送；无 upstream 打开 Push 页并可设置 upstream；推送不卡在凭据提示（`GIT_TERMINAL_PROMPT=0`），认证失败返回 `git/auth-required` 并提供可复制的终端命令。
- [ ] AC7：Push Rejected：非快进被拒时显示原因与远程新提交；「拉取并变基 / 拉取并合并 / force-with-lease」可选，默认拉取并变基；force 需勾选风险确认；自动重试只一次；拉取产生冲突时停在操作横幅并指向控制台。
- [ ] AC8：回滚：已跟踪文件 `restore --worktree`；未跟踪文件删除需危险确认（对象与数量）；取消无副作用（单测 + 实机）。
- [ ] AC9：提交后状态栏、日志（新 HEAD 高亮）、提交页、Tab 圆点同步更新；提交中按钮 loading 且不重复提交；草稿按会话保存、提交成功后清空。
- [ ] AC10：中英双语——A1/A2 所有可见文案走 `gitWorkbench` 命名空间，`en` 与 `zh` 键集一致（类型强制），切换语言后无残留中文（静态扫描测试 + 实机截图）。
- [ ] AC11：A1 遗留 AC3——会话窗口可见时在 DSH 内录制 2000 行日志滚动，前台 fps ≥55 并记录。
- [ ] AC12：`make check` 全绿；`pnpm smoke` 通过；client gzip ≤250KB；安装态复验；验证记录完整。

### T2：Host 提交、Amend、回滚、加入 VCS（待开始）

- **目标**：实现 §8.2.4 普通提交、仅改信息 Amend、§8.2.5 回滚与加入 VCS。
- **涉及文件**：`src/host/git/commit-write.ts`（新）、`src/host/git/rollback.ts`（新）、`src/host/rpc.ts`、`src/shared/protocol.ts`、`test/host/commit-write.test.ts`、`test/host/rollback.test.ts`。
- **接口与要点**：
  - 端点 `commitFiles { sessionId, requestId, paths: string[], message: string, amend?: boolean }` → `{ sha, shortSha, version }`；`amendMessage { sessionId, requestId, message }` → 同上；`rollback { sessionId, requestId, paths, deleteUntracked: boolean }`；`addToVcs { sessionId, requestId, paths }`。
  - 提交：未跟踪路径先 `add -N -- <paths>`，再 `commit --only -m <msg> -- <paths>`（`--amend` 时加 `--amend`）；**失败时对本次 `add -N` 的路径执行 `reset -q -- <paths>` 撤销 intent-to-add**，索引回到提交前。
  - 仅改信息：`diff --cached --quiet` 非零（暂存区有改动）→ `git/index-not-clean`；否则 `commit --amend -m <msg> --only`（不带路径）。
  - 操作进行中（`status.operation !== null`）→ `git/operation-in-progress`（操作状态提交在 A3）。
  - hook 失败：识别 `pre-commit`/`commit-msg` 非零退出 → `git/hook-failed`，`details` 带 stdout/stderr 摘要（已脱敏、≤4KB）。
  - 路径校验沿用 `diff.ts`（相对 POSIX、拒绝 `..`/绝对/`.git`），并拒绝重复与空列表；消息去尾空白后为空 → `git/invalid-payload`。
  - 回滚：已跟踪 `restore --worktree -- <paths>`，按设计 §8.2.5 只丢弃工作区改动；仍有暂存内容的路径在返回值 `keptStaged: string[]` 里列出，客户端提示「暂存区改动已保留」。未跟踪且 `deleteUntracked` 时 `clean -f -- <paths>`（只针对显式路径）；`deleteUntracked=false` 时跳过未跟踪路径并在 `skipped` 里列出。
- **测试（真实临时仓库）**：2/5 勾选只提交 2 个且暂存区无关改动保留；未跟踪/删除/重命名；空格、Unicode、`-` 开头路径；Amend 仅改信息与 `index-not-clean`；hook 失败返回 `git/hook-failed` 且 intent-to-add 已撤销；操作进行中拒绝；回滚已跟踪/未跟踪与 `deleteUntracked=false` 时不删。
- **完成标准**：AC2–AC5、AC8 的 Host 部分有测试证据；`make check` 绿。
- **验证命令**：`pnpm vitest run test/host`。

### T3：Host 推送、推送预览、Push Rejected 拉取（待开始）

- **目标**：§11 Push 与 Push Rejected 所需的 Host 能力。
- **涉及文件**：`src/host/git/push.ts`（新）、`src/host/git/pull.ts`（新）、`src/host/rpc.ts`、`src/shared/protocol.ts`、`test/host/push.test.ts`（用本地 bare 仓库当远程）。
- **接口与要点**：
  - `pushPreview { sessionId }`（读）→ `{ remotes: string[], branch, upstream?, commits: CommitSummary[] (≤100), defaultRemote }`。
  - `push { sessionId, requestId, remote, branch, setUpstream?, forceWithLease?, tags? }` → `{ result: 'ok' } | 拒绝结构`；命令 `push --porcelain [--set-upstream] [--force-with-lease] <remote> <branch>`，**不提供 `--force`**；解析 porcelain：`!` 行 → `git/rejected`，`details.reason` 为 `non-fast-forward | fetch-first | protected | hook-declined | other`，并附远程新提交（`log HEAD..<remote>/<branch>`，fetch 后）。
  - `pullForPush { sessionId, requestId, remote, branch, mode: 'rebase' | 'merge' }` → 成功或 `git/conflict`（停在操作状态，交给 A1 操作横幅与 A3 冲突流程）。
  - 认证失败（`could not read Username`、`Authentication failed`、`Permission denied (publickey)`）→ `git/auth-required`，`details.command` 为可复制的终端命令（不含凭据）。
- **测试**：bare 远程 ok / 非快进被拒 / force-with-lease 在远程被他人更新后失败；set-upstream；pull rebase/merge 成功与冲突；认证错误分类（用假 runner 输出）。
- **完成标准**：AC6–AC7 的 Host 部分有测试证据；`make check` 绿。
- **验证命令**：`pnpm vitest run test/host/push.test.ts`。

## 评审重点（自验证与 AI 评审时特别关注）

- 提交失败（hook、锁、Agent 同时改文件）后索引必须回到提交前：`add -N` 留下的 intent-to-add 不能残留，用户的暂存区不能被改。
- 写操作与 Agent 并发：status 是 3s 前的快照，勾选的文件可能已被 Agent 还原或删除——`commit --only` 报错时给出「文件已变化，刷新后重试」，不能提交到意料之外的内容。
- 凭据：推送绝不能卡在交互提示上；HTTPS URL 里的凭据不能出现在控制台、错误详情或 `details.command` 里。
- 双击、`Cmd+Enter` 连按、提交中切页：同一提交只执行一次（`requestId` + 写队列 + 按钮 loading）。
- detached HEAD：提交允许（提示 detached），「提交并推送」与 Push 页必须要求显式选择远程分支，不推到意外的引用。
