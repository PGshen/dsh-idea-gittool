## 背景

本仓库是 DSH 的独立双面 bundle 插件（Host + Client 同包），官方 tsdown preset 无法脱离 DSH 仓库使用，必须自写产物构建。
harness 要求 `make check` 是唯一质量关口，因此需要一个能同时覆盖 lint、类型检查、分层契约、测试的最小工具链，且不能引入运行时依赖。

## 决定

- **语言**：TypeScript（`strict`），Host 产物为 ESM，Client 产物为浏览器 bundle。
- **包管理**：pnpm（通过 `corepack enable pnpm` 提供），锁定 `packageManager` 与 `pnpm-lock.yaml`。
- **构建**：自写 `build.mjs`，用 esbuild 产出 `lib/host.js` / `lib/client.js`；产物包装与 externals 清单按 [可行性调研](../references/dsh-integration-feasibility.md) §5.2–5.4。
- **测试**：vitest；集成测试在临时目录创建真实 git 仓库；另有不依赖浏览器的产物 smoke（校验 `__ModuleLoader__` 包装）。
- **lint / 格式**：eslint（flat config + typescript-eslint），格式检查并入 eslint。
- **类型检查**：`tsc --noEmit`。
- **分层契约**：dependency-cruiser，规则 R1–R5 见 [ARCHITECTURE.md](../ARCHITECTURE.md) §3 与 [`.dependency-cruiser.cjs`](../../.dependency-cruiser.cjs)。
- **聚合**：`package.json` 的 `check` 依次运行 lint → typecheck → layers → test；`make check` 调用它，`check:fast` 只跑 lint + typecheck。
- **CI**：首发只用本地关口，不接远程 CI；接入时让 CI 直接调用 `make check`。

## 考虑过的其他方案

- **沿用官方 tsdown preset**：不选。它硬编码 DSH 仓库根、`packages/` 布局与基線模块清单，外部包无法解析（调研 §5.3）。
- **用 npm 或 yarn**：不选。pnpm 与 DSH 生态一致，且便于后续在 profile 中 `link:`。
- **用 node:test 代替 vitest**：不选。vitest 的 watch、mock 与 TS 开箱支持更适合后续大量解析/hook 测试；代价是多一个 devDependency。
- **把分层规则写成文档约定**：不选。约定必须机器检查，否则会被反复违反（SOP §10）。

## 影响

- M0 计划 T1 负责创建 `package.json`、安装这些 devDependencies，并把 `check` / `check:fast` 接进 Makefile；在 T1 完成前，`make check` 只跑文档检查。
- 运行时依赖保持为零：Host 只 import `node:*` 与 type-only DSH 包；Client 只使用宿主 baseline externals。
- 每次新增工具都要同步更新本 ADR、Makefile 注释与 [开发环境搭建](../runbooks/dev-setup.md)。
