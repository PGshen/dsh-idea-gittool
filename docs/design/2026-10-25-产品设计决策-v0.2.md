## 2. 范围变更

### 2.1 首发包含（原 P0 + 全部 P1）

**核心闭环（原 P0）**

- 仓库状态、日志、提交图、筛选、分支面板、提交详情、变更文件、统一 diff。
- 按文件提交（`--only`）、Amend（含仅改信息）、提交并推送、回滚、加入 VCS。
- 分支列表/签出/智能签出/新建/删除/重命名/合并/变基/拉取/推送/比较。
- 贮藏 CRUD；冲突最小闭环；操作状态提交；Push Rejected；智能操作。
- Git 控制台、只读模式、写能力门禁、中英双语、明暗主题。

**原 P1（本次一起做）**

- 三栏可编辑合并窗口、逐块 Accept、全部简单冲突、Review Changes、二进制/删除冲突。
- 交互式变基（列表排序、pick/reword/edit/squash/fixup/drop）。
- 并排 diff、词级高亮、忽略空白、折叠未改片段、`n`/`p` 跳块。
- 文件历史、Blame 视图、提交/分支比较、文件级比较。
- 完整提交右键菜单：reword、undo commit、fixup/squash/drop、push up to here、new tag、create patch 等。
- Shelf、Changelist、Worktree 管理、Patch 创建/应用、Remotes 对话框、更多提交选项（author/sign-off/GPG）。
- 文档预览头部 Git 动作（Blame/历史/Diff/状态徽标）；Blame 视图（只读行级注解）。
- 设置页扩展、a11y、性能打磨。

**P2 仍不做**

- 多仓库合并日志、同步分支控制、子模块、LFS、Clone/Init、Local History、托管平台 PR/Issue、内置凭据管理。

### 2.2 优先级标签的新含义

| 标签 | 原含义 | 现在 |
|---|---|---|
| P0 | 首发必须 | 实现顺序第 1 批；首发包含 |
| P1 | 首批增强 | 实现顺序第 2 批；**首发包含** |
| P2 | 远期 | 仍不在首发 |

主设计文档 §6.2 的 P1 行全部视为「首发范围」，不再延后。

### 2.3 发布节奏

- 内部构建：`0.1.0` → `0.2.0` → … 仅用于自测/内测，不对外承诺。
- 对外首发：**`1.0.0`**，一次性包含 P0+P1。
- 风险高的 P1（三栏合并、交互式变基、Worktree）用 feature flag 控制，默认开启前先内部验收；不改变「一次发布」的目标。

## 3. 编辑器装饰 / 行内 Blame 可行性

### 3.1 事实

DSH Web GUI 没有可编辑代码编辑器：

- 文档预览（`ui-sidebar-documentpreview`）是**只读**查看器，没有 caret、选区、编辑缓冲区。
- 没有 Monaco/CodeMirror/编辑器装饰 API、CodeLens、保存事件。
- 文件树（`ui-sidebar-files`）只暴露 `sidebar.right.tab.files.actions`（工具栏动作），**没有行级装饰 slot**。
- 文档预览公开了两个可用扩展点：
  - `sidebar.right.tab.document.actions`：list slot，owner 是 `{ absolutePath }`，渲染在预览头部，适合加「Blame / 历史 / Diff」动作与状态徽标；
  - `ctx.documentPreviews.register({ id, extensions, priority, ... })` + keyed `sidebar.right.tab.document` slot：可以注册一个自定义文档渲染器，实现逐行注解视图。
- 右侧栏页类型可以通过 `ctx.sidebarRight.openTab(kind, { params })` 打开，参数用 `SidebarRightTabParamsMap` 声明合并扩展。

### 3.2 能力矩阵

| 能力 | 能否做 | 方案 | 限制 |
|---|---|---|---|
| 真正的编辑器装饰（文件状态色、gutter 图标、行内 CodeLens） | **不能** | 无编辑器、无装饰 API | 不修改 DSH 仓库；不改其他插件内部 |
| 光标行行内 blame（行尾浅色文字） | **不能** | 无 caret/编辑器缓冲区 | 只读预览没有「当前行」语义 |
| **Blame 视图**（逐行/行段显示提交、作者、日期） | **能** | 新增 Git 页 `git.blame`，或自定义文档渲染器 | 只读；不是覆盖在默认预览上；需要点击进入 |
| **文档预览头部动作**（Blame / 历史 / Diff / 状态徽标） | **能** | `sidebar.right.tab.document.actions` 公共 slot | 只有头部动作，不是文件树/标签页装饰 |
| 文件树行状态色 | **不能** | 无 row slot | 需要 DSH 新增 slot；首发不做，可上游提议 |
| 编辑器标签页状态色 | **部分** | 文档预览头部动作/徽标 | 没有 per-file tab title 装饰 API |
| 自定义文档渲染器（下拉选择「Git Blame」） | **能** | `documentPreviews.register` + keyed body slot | `priority: 'extension'` 可能抢占默认渲染器；不建议默认开启 |
| 行内 blame 悬浮/点击跳提交 | **能** | Blame 视图内 hover card / click | 不是编辑器内联交互 |

### 3.3 推荐方案

**做「Blame 视图」+「文档预览头部动作」，不做编辑器装饰。**

1. **Blame 视图**（P1，首发）
   - 新增页类型 `git.blame`，参数 `{ path: string; sessionId?: string }`。
   - 入口：
     - 文档预览头部动作「Blame」；
     - 提交详情/变更文件右键「Blame」；
     - 文件历史页「Blame」。
   - 内容：文件头（路径、分支、提交）、逐行注解 gutter（短哈希/作者/日期）、语法高亮、点击行 → 该提交详情/该文件 diff、hover card 显示提交信息、大文件分页。
   - 视觉上接近「行内 blame」，但它是独立只读页，不依赖编辑器 caret。

2. **文档预览头部动作**
   - 通过 `ctx.slots.inject('sidebar.right.tab.document.actions', ...)` 注册一个 24px 动作组：状态字母（M/A/D/U）+「Blame」「历史」「Diff」。
   - 使用 owner 的 `absolutePath`；用会话 hook 取 sessionId；调用 `ctx.sidebarRight.openTab('git.blame', { params: { path } })` 或切到 Git tab 的对应页。
   - 这是「编辑器标签页装饰」在 DSH 里最接近的合法形态。

3. **可选：自定义文档渲染器**
   - 如果用户希望「打开文件就是 blame 视图」，可以注册一个 `documentPreviews` 的 `priority: 'extension'` 渲染器，标题「Git Blame」，在预览下拉里可选。
   - **默认不启用**：它会参与默认渲染器竞争，可能替换内置代码预览；用设置项显式开启，并在 README 说明影响。
   - 不作为首发默认路径。

4. **文件树状态色**
   - 不做。`ui-sidebar-files` 没有行级 slot，独立插件无法安全注入；如确实需要，向 DSH 提议新增 `sidebar.right.tab.files.row` 之类的 slot，再另行实现。

### 3.4 技术要点

```ts
// 文档头部动作（示意）
ctx.effect(() => ctx.slots.inject('sidebar.right.tab.document.actions', () => ctx.slots.register(
  { name: 'sidebar.right.tab.document.actions', key: 'idea-git.file-actions', locale: NS },
  FileGitActions, // props: { absolutePath }
)))

// 打开 Blame 页（示意）
ctx.sidebarRight.openTab('git.blame', { params: { path: absolutePath } })

// 页类型声明（示意）
declare module '@deepseek-ai/dsh-client-ui-sidebar-right' {
  interface SidebarRightTabParamsMap {
    'git.blame': { path: string; sessionId?: string }
  }
}
```

- Blame 数据：`git blame --line-porcelain -- <path>`，按 commit 合并连续行；单次最多 2000 行，超出分页；仓库根不在沙箱内时只读仍可用。
- 不修改 `ui-sidebar-documentpreview` / `ui-sidebar-files` 的任何内部实现；只使用公开 slot 与 registry。
- 如果 `document.actions` 在当前 DSH 版本不可用，降级为 Git tab 内的「Blame」入口，并在 README 记录版本要求。

### 3.5 对产品文案的影响

- 不使用「Inline Blame」这个词，改用「Blame 视图」/「逐行注解」。
- 设置项：「在文档预览中显示 Git 动作」默认开；「使用 Git Blame 渲染器作为默认代码视图」默认关。
- 不承诺「行号栏装饰」「编辑器状态色」；对外说明这是宿主限制。

## 4. 实施计划（单次发布，内部分阶段）

| 阶段 | 内容 | 估时（单人全职） |
|---|---|---|
| **M0** | 设计定稿 + 集成 spike：bundle 构建/安装、`status`/`log`、cwd、沙箱写门禁、刷新、HMR/重启 | 0.5–1 天 |
| **A1 核心只读** | 入口/tab、仓库栏、日志+提交图、详情/变更文件/diff、分支面板、控制台、只读模式 | 3–5 天 |
| **A2 提交闭环** | 变更树、按文件提交、Amend、提交并推送、回滚、Push/Rejected、写门禁 | 3–5 天 |
| **A3 分支/贮藏/冲突最小闭环** | 分支动作/对话框、贮藏、操作状态提交、智能操作、冲突列表 | 5–7 天 |
| **B1 三栏合并** | 冲突列表增强、三栏可编辑、逐块 Accept、简单冲突、Review Changes | 4–7 天 |
| **B2 历史与 Blame** | 文件历史、Blame 视图、文档头部动作、比较模式 | 3–4 天 |
| **B3 高级操作** | 交互式变基、完整提交菜单、Shelf、Changelist、Worktree、Patch、Remotes、并排 diff/词级 | 5–8 天 |
| **B4 打磨** | a11y、性能、i18n、跨平台、安装/升级验证、文档 | 3–5 天 |
| **合计** | 含缓冲 | **约 6–9 周** |

说明：

- 这是「一次发布」的工程排期，不是对外发布批次；内部 `0.x` 构建用于验收。
- 三栏合并、交互式变基、Worktree 风险最高，先做技术 spike/feature flag；如果某项严重超期，单独评估是延期发布还是降级，不静默砍掉。
- 与参考项目相比，首发覆盖其绝大多数 Git 能力；明确不做的只有编辑器装饰、Local History、多仓库/子模块/LFS/托管平台集成。

## 5. 新增风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| S1 | 一次性做 P0+P1，范围大、QA 面广 | 高 | 内部阶段验收 + feature flag；每个阶段结束跑真实仓库回归；不把 P1 风险项留到最后 |
| S2 | 三栏合并编辑器成本高 | 高 | 先做只读块 + 可编辑 Result 的最小闭环，再补曲线/词级；必要时降级为逐块 Accept + 终端兜底 |
| S3 | 交互式变基的 todo/sequence editor 跨平台复杂 | 中 | Host 生成 todo + `GIT_SEQUENCE_EDITOR` 脚本；Windows 路径/引号专项测试；失败可回退命令行 |
| S4 | 文档预览 action slot / registry API 变动 | 中 | 用公开 API；不可用时降级为 Git tab 入口；`engines.dsh` 锁定 + 升级冒烟 |
| S5 | 一次发布导致回归发现晚 | 高 | 内部 `0.x` 构建 + 真实仓库矩阵（10k 提交、脏工作区、冲突、沙箱外、Windows CRLF） |
